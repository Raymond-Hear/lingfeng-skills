# 风险等级定义

本文档定义了GitHub安全检查中使用的风险等级标准。

## 风险等级表

| 风险等级 | 图标 | 分数 | 处理优先级 | 说明 |
|---------|------|------|-----------|------|
| **严重** | 🔴🔴🔴 | 90-100 | P0 - 立即修复 | 极度敏感，立即处理 |
| **高** | 🔴🔴 | 70-89 | P1 - 优先处理 | 高度敏感，尽快处理 |
| **中高** | 🟠 | 50-69 | P2 - 计划处理 | 中度敏感，建议处理 |
| **中** | 🟡 | 30-49 | P3 - 择机处理 | 需要注意，可以处理 |
| **低** | 🟢 | 10-29 | P4 - 可选处理 | 轻微问题，可选处理 |
| **配置** | 🔵 | N/A | P3 - 配置优化 | 配置优化建议 |

## 风险评估标准

### 1. 敏感程度评分 (40分)

| 敏感程度 | 分数 | 说明 |
|---------|------|------|
| 极度敏感 | 40 | 生产环境凭证、完全访问权限 |
| 高度敏感 | 30 | 测试环境凭证、重要权限 |
| 中度敏感 | 20 | 只读权限、有限权限 |
| 轻度敏感 | 10 | 开发环境、演示用途 |
| 不敏感 | 0 | 公开信息 |

### 2. 影响范围评分 (30分)

| 影响范围 | 分数 | 说明 |
|---------|------|------|
| 严重 | 30 | 数据泄露、经济损失、服务中断 |
| 重大 | 20 | 未授权访问、隐私泄露 |
| 中等 | 10 | 信息暴露、潜在风险 |
| 轻微 | 5 | 轻微信息泄露 |
| 无影响 | 0 | 无实际影响 |

### 3. 可利用性评分 (30分)

| 可利用性 | 分数 | 说明 |
|---------|------|------|
| 极高 | 30 | 直接利用，无需额外条件 |
| 高 | 20 | 需要简单条件即可利用 |
| 中 | 10 | 需要一定条件才能利用 |
| 低 | 5 | 难以利用或价值有限 |
| 无 | 0 | 无法利用 |

## 风险等级计算

```
总分 = 敏感程度分数 + 影响范围分数 + 可利用性分数

风险等级判定:
- 90-100分: 🔴🔴🔴 严重 (P0)
- 70-89分: 🔴🔴 高 (P1)
- 50-69分: 🟠 中高 (P2)
- 30-49分: 🟡 中 (P3)
- 10-29分: 🟢 低 (P4)
- 0-9分: 无需处理
```

## 典型场景风险评估

### 场景1: 生产环境API密钥泄露

```
敏感程度: 40/40 (生产环境、完全权限)
影响范围: 30/30 (经济损失、数据泄露)
可利用性: 30/30 (直接利用)

总分: 100/100
风险等级: 🔴🔴🔴 严重 (P0)
```

### 场景2: 测试环境数据库密码

```
敏感程度: 30/40 (测试环境)
影响范围: 20/30 (数据访问)
可利用性: 20/30 (需要网络访问)

总分: 70/100
风险等级: 🔴🔴 高 (P1)
```

### 场景3: 开发者本地路径

```
敏感程度: 10/40 (开发环境)
影响范围: 10/30 (信息暴露)
可利用性: 5/30 (难以利用)

总分: 25/100
风险等级: 🟢 低 (P4)
```

### 场景4: README中的邮箱地址

```
敏感程度: 10/40 (个人信息)
影响范围: 10/30 (垃圾邮件)
可利用性: 10/30 (可用于联系)

总分: 30/100
风险等级: 🟡 中 (P3)
```

### 场景5: 内部API地址

```
敏感程度: 20/40 (内部信息)
影响范围: 15/30 (服务探测)

总分: 50/100

```

## 处理优先级时间表

| 优先级 | 处理时间 | 说明 |
|--------|---------|------|
| P0 | 立即（今天） | 可能造成严重后果 |
| P1 | 尽快（本周） | 重要安全问题 |
| P2 | 计划（本月） | 中等风险 |
| P3 | 择机（有时间） | 一般风险 |
| P4 | 可选 | 轻微问题 |
