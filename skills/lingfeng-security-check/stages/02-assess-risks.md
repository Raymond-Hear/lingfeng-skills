# 阶段2：评估风险和影响

## 目标
对阶段1发现的问题进行风险评估，分析潜在影响，确定处理优先级。

## 评估框架

### 风险等级定义

| 风险等级 | 图标 | 说明 | 处理优先级 |
|---------|------|------|-----------|
| **严重** | 🔴🔴🔴 | 极度敏感，立即处理 | P0 - 立即修复 |
| **高** | 🔴🔴 | 高度敏感，尽快处理 | P1 - 优先处理 |
| **中高** | 🟠 | 中度敏感，建议处理 | P2 - 计划处理 |
| **中** | 🟡 | 需要注意，可以处理 | P3 - 择机处理 |
| **低** | 🟢 | 轻微问题，可选处理 | P4 - 可选处理 |

### 风险评估维度

#### 1. 敏感程度评估

**凭证和密钥**
```
评估标准：
- 是否是生产环境密钥？
- 密钥的权限范围（读/写/管理）？
- 是否可以立即撤销？
- 密钥的过期时间？

风险等级：
🔴🔴🔴 严重: 生产环境、完全权限、无法撤销
🔴🔴 高: 测试环境、完全权限、可以撤销
🟠 中高: 只读权限、短期有效
🟡 中: 开发环境、有限权限
🟢 低: 已过期、演示用途
```

**个人信息**
```
评估标准：
- 信息的可识别性？
- 信息的公开程度？
- 是否可以轻易更改？

风险等级：
🟡 中: 邮箱、电话（可更改）
🟢 低: 姓名（可能已公开）
```

**本地路径**
```
评估标准：
- 路径是否暴露系统结构？
- 是否包含用户名？
- 是否有安全风险？

风险等级：
🟡 中: 包含用户名的完整路径
🟢 低: 相对路径或通用路径
```

#### 2. 影响范围评估

**如果信息泄露会导致什么？**

| 泄露类型 | 潜在影响 | 影响程度 |
|---------|----------|----------|
| API密钥 | 未授权访问、数据泄露、费用损失 | 🔴🔴🔴 |
| 数据库密码 | 数据库完全暴露、数据泄露 | 🔴🔴🔴 |
| Token | 冒用身份、未授权操作 | 🔴🔴 |
| 个人邮箱 | 垃圾邮件、钓鱼攻击 | 🟡 |
| 本地路径 | 系统信息暴露 | 🟢 |
| 内部API地址 | 服务被探测 | 🟠 |

#### 3. 可利用性评估

**攻击者能否利用这个信息？**

| 信息类型 | 可利用性 | 说明 |
|---------|----------|------|
| API密钥 | 高 | 直接可用于API调用 |
| 数据库密码 | 高 | 可直接连接数据库 |
| Token | 高 | 可用于身份认证 |
| 邮箱地址 | 中 | 可用于钓鱼或垃圾邮件 |
| 本地路径 | 低 | 信息价值有限 |
| 注释中的信息 | 低 | 通常难以利用 |

## 风险评估流程

### 步骤1：逐项评估

对阶段1发现的每个问题进行评估：

```
问题: config.py:15 - API密钥
────────────────────────────────────────────
1. 敏感程度: 🔴🔴 高
   - 类型: OpenAI API密钥
   - 权限: 完全访问权限
   - 可撤销: 是
   - 过期时间: 无永久

2. 影响范围: 🔴🔴🔴 严重
   - 直接经济损失: 可能（API调用费用）
   - 数据泄露: 可能
   - 服务中断: 可能

3. 可利用性: 🔴🔴🔴 高
   - 可直接用于API调用
   - 无额外防护

综合风险等级: 🔴🔴🔴 严重 (P0)
────────────────────────────────────────────
```

## 特殊情况处理

### 情况1：已提交到Git历史

```
问题: 敏感信息已经提交到Git历史
───────────────────────────────────────────────────────────
风险等级: 🔴🔴🔴 严重
原因: 即使删除文件，历史记录仍然可见

处理建议:
1. 立即撤销泄露的凭证（API密钥、密码等）
2. 使用 git-filter-repo 或 BFG Repo-Cleaner 清理历史
3. 强制推送到远程（注意：谨慎操作）
4. 通知所有协作者重新克隆仓库

命令示例:
# 使用 BFG Repo-Cleaner
bfg --replace-text passwords.txt
bfg --delete-files env-file

# 或使用 git-filter-repo
git filter-repo --invert-paths --path .env

# 强制推送（谨慎！）
git push origin --force --all
───────────────────────────────────────────────────────────
```

### 情况2：公开仓库中的敏感信息

```
问题: 敏感信息在公开仓库中
───────────────────────────────────────────────────────────
风险等级: 🔴🔴🔴 严重
原因: 任何人都可以看到

紧急处理步骤:
1. ⚡ 立即撤销所有泄露的凭证
2. ⚡ 立即更改所有泄露的密码
3. 🔄 清理Git历史
4. 🔄 强制推送
5. 📢 检查是否有异常访问/使用
6. 🔒 启用额外安全措施（2FA等）

预防措施:
- 使用 pre-commit hook 检查敏感信息
- 定期审计提交历史
- 使用 git-secrets 等工具
───────────────────────────────────────────────────────────
```

### 情况3：第三方库中的密钥

```
问题: node_modules或依赖目录中包含密钥
───────────────────────────────────────────────────────────
风险等级: 🟡 中
原因: 依赖目录通常会被.gitignore忽略

处理建议:
1. 确认依赖目录在.gitignore中
2. 如果已提交，添加到.gitignore并删除
3. 检查依赖包是否正常（是否被篡改）

验证:
cat .gitignore | grep node_modules
git rm -r --cached node_modules
git add .gitignore
───────────────────────────────────────────────────────────
```

## 注意事项

- 优先处理可能导致直接损失的问题
- 考虑信息的可利用性，不仅仅是敏感性
- 已公开的敏感信息需要立即处理
- Git历史中的敏感信息特别危险
- 提供具体的处理建议，不只是警告
