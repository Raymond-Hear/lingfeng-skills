# 网页文案编辑指南

## 先看访客在哪一步

一起读附近的标题、按钮、链接和状态。同一句「继续」在表单下一步和开始付款时，给用户的信息不同。确认这块内容需要回答的事：访客遇到了什么、这里能帮他做成什么、接下去能点什么。优先使用产品已经有的术语和真实操作。如果只拿到截图或文案，就以能确认的信息做一版；缺少的功能、可用状态或结果留在交付说明里。

## 先删，再改

- **删可套用在任何产品上的话。** 如果一句话换掉产品名也成立，比如「打造属于你的高效知识工作流」，先看是否能换成这款产品做得到的具体动作和结果。没有新信息的眉题、同义副标题、重复的按钮说明可以删。删不动的原因通常是这句还承载着范围、条件或下一步。
- **用用户熟悉的词说实事。** 用「把笔记导出为 Markdown」「断了会自动重试」这类具体表达。少用「释放价值」「开启全新体验」这类抽象动宾结构，以及对仗口号、硬凑三项的卖点和连续反问。保留读者确实使用的术语和已有品牌语气。中文按自然语序读一遍，正式场景用朴素、准确的词。
- **按位置决定写几句。** 首页标题先说产品能做什么，副标题补一个有价值的场景、适用范围或限制。功能说明说清什么情况下会发生什么。按钮写明执行的动作或跳转目的。空状态、失败和完成提示先说当前结果，再给真实可用的下一步。权限、删除、收费或数据去向用直白的表述。
- **守住原有事实。** 保留适用对象、支持范围、前置条件、数量、失败后的处理和涉及隐私的承诺。比如实际是「网络恢复后尝试重连」，成稿仍应保留「网络恢复后」和「重试」。「一定续上」「自动完成」是更强的承诺，需要产品行为支持。品牌主张、数字、时限和上线计划同样要有依据。

## 例子

| 场景 | 原文 | 可以怎么写 |
| --- | --- | --- |
| 笔记工具首屏，确认支持原文或 AI 总结 | 释放知识资产的无限潜能，打造属于你的高效工作流 | 标题「把笔记导出为 Markdown」。补一句「可下载原文或 AI 总结，留作本地备份」。主按钮「打开导出工具」。 |
| 下载中断，确认网络恢复后会重试 | 全程无忧，轻松掌控每一次下载 | 网络恢复后，会自动重试中断的下载。 |
| 官方商店有上线计划，目前只有 ZIP 可用 | Chrome 扩展链接待公布 | 商店状态「即将上线」，当前按钮「下载 ZIP」。 |
| 搜索无结果，界面有清除筛选操作 | 这里空空如也，探索更多可能 | 没有符合筛选条件的笔记。按钮「清除筛选」。 |
| 同步暂停，确认已保存进度 | 哎呀，出了一点小问题！ | 同步已暂停，进度已保存。按钮「继续同步」。 |

## 放回原位置复读

按访客顺序读一遍。如果只看到标题和主按钮，能否说出产品用途和接下来会发生什么？再看每条状态和按钮是否匹配实际功能，术语与同一流程是否一致。能预览页面时检查窄屏折行，以及较长名称、动态数值等会不会把关键信息挤出可见区域。

做评审时，把最影响理解或操作的原句和建议成稿并列，解释一句关键改动。用户授权直接改页面时，按目标范围落地，检查相关位置的显示与动作。只要成稿时，按原页面顺序给可直接粘贴的标题、说明和按钮文案。
