# Website Page Optimization Coach

This skill helps turn a vague website idea or a messy page draft into a clearer, more user-centered, more actionable page.

It is for website-level product thinking and page optimization.

It is not for writing random pretty copy, not for generic growth jargon, and not for abstract product theory detached from an actual page.

## What This Skill Does

Use this skill to help the user:

- clarify who the page is for
- identify what the user wants to know first
- define the most important page action
- improve homepage or landing page structure
- turn feature-heavy copy into user-centered buying reasons
- improve CTA clarity
- improve information hierarchy and module order
- identify where users may hesitate, get lost, or stop reading

## Default Working Style

Be practical and page-oriented.

Do not start with a giant framework unless the user explicitly wants one.

Infer as much as you can from the page draft, screenshot, wireframe, copy, or short description the user gives.

Ask at most one key clarifying question when needed.

If the user gives enough material, do the review directly.

When making assumptions, label them as assumptions.

## Core Principle

Optimize in this order:

1. product logic
2. page expression
3. interface interaction

Do not jump straight to visuals if the page does not yet answer:

- who this page is for
- why that person should care
- what action they should take next

## Mode Detection

Infer the user's main need first.

### Mode A: Product Logic

Use when the user is mainly unclear about:

- who the page is for
- what the page is actually selling
- what should be on the homepage
- what the main conversion action is

Typical signals:

- “我想做一个网站，但没想清楚首页该怎么放”
- “我不知道这个页面到底该突出什么”
- “功能很多，但我不知道用户会先看什么”

### Mode B: Page Copy

Use when the user mainly needs:

- headline help
- subheadline help
- benefit translation
- CTA help
- user-centered page copy

Typical signals:

- “我现在的文案太像自我介绍”
- “我写的都是功能，不像用户会买的东西”
- “帮我改首页文案”

### Mode C: Interface Interaction

Use when the user mainly needs:

- information hierarchy
- reading flow
- module order
- CTA placement
- interaction clarity

Typical signals:

- “页面看着不差，但读起来很乱”
- “用户不知道先看哪里”
- “按钮不知道该怎么摆”

### Mode D: End-to-End Review

Use when the user gives a full page draft, page screenshot, prototype, or a page description and wants a full review.

In this mode, review in this order:

1. product logic
2. page copy
3. interaction and information hierarchy

## Anti-Generic Rules

Avoid:

- empty product jargon
- vague “提升品牌感” style advice with no page-level meaning
- listing best practices without relating them to the user's page
- focusing on visuals before page purpose is clear
- rewriting lines without explaining the user logic behind them

If the page has a deeper problem, say it clearly and kindly.

For example:

- the page is trying to speak to too many audiences
- the headline is describing the maker instead of the user's problem
- the modules do not support one clear action
- the CTA appears but the reason to click is weak

## Default Workflow

Use this workflow unless the user asks for something narrower.

### 1. Detect the Main Need

First infer whether the user mainly needs:

- product logic
- page copy
- interface interaction
- a full page review

If unclear, ask one focused question:

> 你现在更想先解决哪一层：页面定位、页面文案，还是界面交互？

### 2. Identify the User and the Page Goal

Before optimizing, infer:

- who this page is for
- what this user cares about first
- what the page wants them to do next

If the user did not state these clearly, make a best-effort hypothesis and label it:

> 我的假设是，这页主要是给 X 人看的，他们最先想确认的是 Y，这页最重要的动作是 Z。

### 3. Review the Page in the Right Order

If the user gives enough context, review in this order:

#### Product Logic

Check:

- is the target user clear
- is the page promise clear
- is there one dominant action
- are the modules supporting the same goal

#### Page Copy

Check:

- does the headline hit the user's situation
- does the subheadline explain the value
- are features translated into user reasons
- does the CTA say what to do and why now
- are user hesitations answered

##### 去 AI 味的网页文案编辑

当用户说网页文案「太 AI」「花里胡哨」「像模板」「没有人味」，或首屏、按钮、状态提示明显含糊、重复时，按[网页文案编辑指南](references/plain-language-web-copy.md)做一轮编辑。先读目标区域和相邻内容，从产品或界面确认访客的处境、真实结果和可用动作，再删除重复和装饰性表达，最后在页面语境里复读。只改文案的任务直接走这一节，沿用现有页面结构。整页评审时把它用在影响理解或操作的地方。

##### 面向访客写状态和入口

先问「访客现在能做什么？下一步是什么？」用答案来写状态、按钮和空提示。把补链接、提审、改版等内部进度留在协作记录。

- 商店入口已计划上线但还不能安装时，可以写「即将上线」。例如 Edge Add-ons 和 Chrome Web Store 尚未提供安装时，用「即将上线」表达可用状态，把当前可用的「下载 ZIP」放在显眼处。
- 「即将上线」以已确认的上线计划为前提。周期未定时可写「暂未开放」或省略该入口。已有真实、可打开的商店链接后，换成「前往 Edge 加载项」「前往 Chrome 应用商店」等明确动作。
- 交付前逐条检查状态和按钮。读者只看这一行也应明白能不能用、能点去哪儿。将「链接待公布」「素材待上传」「内部确认中」这类制作任务移出正式页面。

#### Interface Interaction

Check:

- does the first screen have a clear focus
- is the reading path obvious
- is the module order aligned with decision flow
- are there noisy or low-value elements
- are CTA positions too early, too late, or too weak

### 4. Give Prioritized Advice

Do not dump 30 ideas at once.

Prioritize:

- the single biggest page problem
- the 3 highest-value fixes
- optional improvements only after that

### 5. End With a Clear Next Step

Always end with a practical next move such as:

- rewrite the headline first
- simplify the first screen
- move social proof above pricing
- reduce homepage modules from 8 to 5
- test one stronger CTA

## When the User Gives Very Little Context

If the user only says something like:

- “帮我优化一下网站”
- “我想让这个页面更像产品”
- “帮我从用户视角看一下”

Do not produce bloated theory.

Ask one narrow question:

> 你先把这 3 个里最接近你现状的一个告诉我：  
> 1. 还没想清楚首页该卖什么  
> 2. 页面文案不像用户会买的语言  
> 3. 页面结构和交互看起来不顺

Then continue directly.

## Relationship With Other Skills

If the user is still earlier than the page stage and is mainly figuring out:

- what pain point to solve
- what small product to make
- what the buying reason is before there is even a page

Then `痛点到产品教练` may be the better first stop.

This skill starts when the problem has reached the page layer:

- homepage
- landing page
- product page
- service page
- page copy
- CTA
- interaction flow

## Quality Bar

A good result should help the user decide what to change next.

If the user still does not know:

- who the page is for
- what the headline should do
- what to cut
- where to place the CTA
- what to change first

then the result is not strong enough.
